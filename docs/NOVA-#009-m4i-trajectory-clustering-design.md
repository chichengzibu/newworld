# NOVA #009 — M4-I 轨迹签名聚类（学习闭环不再只认字面相同的指令）

> **状态**：已实现（2026-11-06）
> **对应台账**：DEV-127 ~ DEV-130
> **分支**：`feat/harness-wiring`
> **前置**：[M4-C 模式证据链](NOVA-#009-m4c-pattern-evidence-design.md)（轨迹数据结构）

## 一、为什么做这件事

### 1.1 一个用户能直接感知的缺口

旧实现的聚类键是**归一化后的指令文本**。于是：

```
「整理一下桌面」×2
「收拾下桌面」   ×2      ← 做的是同一套动作
```

分成两个簇，每个支持度 2 —— 刚好够门槛。但如果是各 1 次：

```
「整理一下桌面」×1
「收拾下桌面」   ×1
```

两个簇各支持度 1 → 低于 `MIN_SUPPORT(2)` → **永远不提提案**。

而「同一件事的不同说法」恰恰是最值得学的模式 —— **用户不会每次都用一样的措辞**。
旧实现等于要求用户精确重复自己的话，才算「重复」。

### 1.2 业界四个独立工作收敛到同一结论

查 GitHub / 论文时发现，这个问题**不是我想当然**，是有共识的：

| 工作 | 结论 |
|---|---|
| **TraceGraph**（arXiv:2605.31308） | 把 agent 每一步编码成稀疏可观察键（动作/工具类型、观察模式、上下文线索），相似度用**键重叠**算，**不依赖提示词文本** —— 明确指出按提示词聚类会丢掉有区分度的那个维度 |
| **Hierarchical Clustering of Agent Traces**（2026-05） | 对 agent 轨迹存在**结构行为信号**（`tool_call_sequence` = 去重后的有序工具名、`distinct_tools_invoked`、`tool_error_count`…），而 chat 日志没有这些 —— 按提示词聚类等于扔掉区分维度 |
| **AgentTrails**（arXiv:2607.18816） | 把日志转成数据流图后**跨运行对齐**，高支持度的簇被提议用来播种可复用技能库 |
| **Microsoft context-intelligence-gds** | Session→Tool 二部图 + `nodeSimilarity`(Jaccard) / `fastRP` / `node2vec` 找「角色等价但邻居不完全相同」的会话；并警告**比较前必须加权**，否则被胶水工具主导 |

**结论一致**：轨迹的**结构行为信号**才是区分维度。

## 二、实现

### 2.1 签名：轨迹用到的工具（有序去重）

`toolOf(step)` 认三种形状：

| 来源 | 形状 |
|---|---|
| agent loop | `{ name: 'Read' }` |
| TaskExecutor | `{ type: 'run_command' }` / `{ action: 'write_file' }` |
| 旧观察 | `{ description: '...' }`（退化：取首词） |

### 2.2 加权：IDF 压制胶水工具

```
idf(t) = log((1 + N) / (1 + df(t))) + 1      ← 平滑 IDF
sim(A,B) = Σ min(a_t, b_t) / Σ max(a_t, b_t)  ← 加权 Jaccard
```

N = 轨迹条数，df(t) = 含工具 t 的轨迹条数。

### 2.3 踩到的坑：裸 IDF 在小语料下退化

第一版用标准 IDF `log(N / df(t))`。实现期测试直接暴露：

> 出现在**全部**轨迹里的工具 → idf = log(1) = **0** → 权重为零。
> 而学习闭环的分析窗口常常只有几条观察 —— 语料一少，
> **每个工具都出现在所有轨迹里** → 所有权重都是 0 → 相似度恒为 0
> → **一条都聚不到一起**（实测：2 条相同动作的轨迹聚不成簇）。

**平滑 IDF** 解决：权重恒 ≥ 1，任何语料规模都能算相似度；
罕见工具权重仍显著高于胶水工具（N=4 时 2.22 vs 1.0）。

→ 胶水工具的压制从「绝对归零」变成「**相对降权**」，效果一样但不会把小语料打瞎。

### 2.4 贪心聚类

```
每条观察 → 找与已有簇质心最像的那个
  相似度 ≥ 0.5 → 并入(质心 = IDF 加权平均)
  否则 → 自成一簇
```

**为什么贪心而不是层次聚类**：轨迹量级只有几十~几百，层次聚类的 O(n²) 距离矩阵没必要；
贪心结果**可解释** —— 能说清「这条轨迹和哪几条归到了一起」，层次聚类的树没人看得懂。

**确定性**：按输入顺序处理，不引入随机 —— 同一批观察两次聚类结果相同，才能做回归对比。

### 2.5 指令文本没白扔

聚类**键**换成轨迹签名，但簇的**代表指令**取簇内最高频的那条 ——
提案的 name / description / triggerCondition 来自它，**用户自己的话最贴切**。

**没有轨迹的老数据**（M4-C 之前落盘的）→ 退回按指令分组，**不被丢掉**
（那会让老数据永远学不到）。

## 四、遗留与后续

| # | 遗留 | 归属 | 说明 |
|---|---|---|---|
| 1 | **相似度阈值 0.5 是拍的** | 后续 | 需要真实轨迹数据来标定。业界也没有通用阈值 |
| 2 | **只用了工具集，没用顺序与观察结果** | 后续 | TraceGraph 还用「观察模式」（文件不存在、测试通过…）。本项目已有 `hadToolFailure` 与错误分类，可作下一维 |
| 3 | **簇内支持度仍按观察累加** | 口径 | 一条观察含多次执行时，轨迹条数多于观察数 —— 支持度按 `occurrences` 累加，与轨迹数口径不同（已在证据链里标注） |
| 4 | **没有项目级技能自动发现** | 后续 | Anthropic 规范里项目级技能按 cwd 自动发现。本批是「用户手动挂目录」 |
