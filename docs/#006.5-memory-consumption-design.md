### 检索质量验收案（以案计, #006.5·A 案修订）

**Q1 实现稿**（`tests/unit/memory-consumption-006-5.test.ts:46-64` 实文, **同文必 top-1**）：
```
1. 写侧 store: 3 条 content (用户偏好 14 寸 / 机械键盘 / 续航 8h), flush
2. 重启模拟: 新 MemoryVectorStore 实例 loadFromDisk, size() === 3
3. 读侧: 对每条 content 原文作 query (i 0..2)
         → search(qv_i, topK=3, minScore=0.0)[0].entry.id === `q1-${i}`
   — 余弦恒 = 1.0 (同文 = 同哈希向量), 与阈值/minScore 解耦, 必 top-1
```
**断言口径**: **管线验收**（store → persist → load → search 四跳全走通）, **非语义召回**。

**不可行性依据（禁用"≥2/3 语义召回"断言）**:
`EmbeddingService.ts:154-165` 实文 stub 实现:
```ts
private hashToVector(text: string): number[] {
  const hash = createHash('sha256').update(text).digest()
  const hash2 = createHash('sha256').update(hash).digest()
  for (let i = 0; i < this.dimension; i++) {
    const byte = i < hash.length ? hash[i] : hash2[i - hash.length]
    vector.push((byte - 127.5) / 127.5)
  }
  ...
}
```
→ **stub 向量 = 文本纯 SHA-256 哈希**（确定性、零网络、零语义相似性）。
→ 3 条不同文本的 64 维向量两两余弦 ≈ 0（伪随机均匀分布）。
→ 用"用户要什么样的笔记本"作 query 的向量跟 3 条中的任何一条余弦都 ≈ 0。
→ minScore 0.4/0.5 过滤后 **topK=3 全零命中**，"召回 ≥ 2/3" 断不出。
→ 断"语义召回相近"= **虚构**（stub 非真实语义模型, 踩"禁止虚构能力"红线）。
→ 正确口径 = "同文必 top-1"证明管线走通 + minScore 高阈值排除行为单独测（见 Q2）。

**Q2 minScore 高阈值排除断言（#006.5·A 案 c 项新增）**：
```
1. store({ id:'q2', content:'Q2 探针串 Z1-alpha-beta', score:80 }), flush
2. reload 新实例, search(qv_same, topK=3, minScore=0.0)   [同文 query]
   → 命中 1 条, score ≈ 1.0 (top-1)
3. search(qv_other, topK=3, minScore=0.99)  [异文 query, 高阈值]
   → 期望: 0 条 (残差余弦 < 0.99 → 全排除)
```
**断言口径**: **minScore 过滤行为**断言闸 —— 生产 R-2 用 0.7 是**语义召回闸**, 但闸的行为本身（score < minScore 被排除）必须有测试覆盖。
**既有覆盖面核实**（`grep -rn minScore tests`）：
- `memory-consumption-006-5.test.ts:100` 仅 R-2 用 0.0 (闸关闭态), **无一条"高阈值排除"断言**。
- → A 案 c 项**必须补 Q2** (不能靠指认既有覆盖)。
