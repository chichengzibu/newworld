## 一、为什么做这件事

本批修两处**「看起来在工作，其实没有」** —— 这是这个项目最在意的那类缺陷。

### 1.1 兜底占位实现回了一句像正常答复的话

`main.ts` 的注册顺序：

```ts
① ChatManager.registerAgent(asAgentBrain(AgentBrainImpl.getInstance()))      // 脚手架 stub,永远成功
② try { registerAgent(asAgentBrain(LlmAgentBrain.getInstance() ...)) }        // 真实 tool loop,失败则保留 ①
```

所以当真实 brain 注册失败时（provider 配置有问题、模块加载出错），用户面对的是 stub。

而 stub 旧实现回的是：

```ts
payload: { text: `思考完成: ${thinking.userMessage.slice(0, 50)}` }
```

**「思考完成: 帮我把桌面上这些 PDF 归档一下」** —— 这看起来像一个正常的 AI 答复，
但其实**什么都没处理**。用户会以为模型想过了、答了。

主进程那边其实有 `log.warn('LlmAgentBrain 注册失败...')`，但**用户永远看不到**。

这是本项目最不能接受的一类 bug：用户以为 AI 在工作，其实没有。

### 1.2 定价表是双重死代码

M3-E 把成本面板接通后，我记下一条遗留：「`setPricing` 零调用方」。深挖一层，
它是**双重**死的：

| # | 问题 | 后果 |
|---|---|---|
| ① | 零调用方 | 用户没法给自己用的模型配价 |
| ② | **只改内存 Map，不落盘** | 就算调了，重启即丢 |

而用户自己的模型（API 中转站的模型名、私有部署的模型名）**不在默认表里** →
`lookupPricing` 落空 → 成本恒 0 → 成本面板永远是 `$0.0000`，
**却看不出原因**（既可能是没花钱，也可能是没配价，界面上长得一模一样）。

## 二、设计依据

### 2.1 诚实必须写在用户唯一能看到的地方

用户侧唯一能看到的就是那条回复。所以诚实不能只记在主进程日志里 ——
它必须写在**回复正文**里，并且消息本身要带上**结构化标记**（而不是只靠一句话）。

### 2.2 定价要能被用户维护，但要诚实区分「免费」与「没配」

- 本地模型成本 0 是**事实**（没有 API 费用），不是记账失败
- 未知模型成本 0 是**缺数据**

两者在界面上长得一样，用户无从判断。所以定价必须可配，且默认表与自定义要能区分。

## 三、实现

### 3.1 兜底占位实现的诚实化

**回复正文**（`electron/agent/AgentBrain.ts`）：

```
⚠️ 未接入真实模型:当前运行的是兜底占位实现,**没有真正处理你的请求**。

请检查「设置 → 模型管理」里是否配置了可用的 provider 与 API Key;
若已配置,请查看主进程日志里 LlmAgentBrain 注册失败的报错。
```

**结构化标记**：载荷带 `stub: true` → `ChatManager` 把消息状态标成 `'stub'`
（`MessageStatus` 新增该值）。

为什么要有结构化标记而不只是正文里一句话：
「这条是占位答复」应该是**可查询的事实**，将来统计「有多少次是兜底答复」
不用去猜正文。

### 3.2 定价持久化 + IPC + UI

| 层 | 改动 |
|---|---|
| `CostTracker` | `setPricing` 现在**落盘**（`cost-pricing.json`，与用量记录**分开** —— 用量频繁追加、定价极少变，同文件会让「改一次定价」重写整个用量数组）；新增 `listPricing()`（区分默认/自定义） |
| 默认表 | 补 `ollama-qwen3.5` / `ollama-bge-m3` / `ollama-qwen3.8` —— 本地模型成本确实是 0，但要有条目才能归到「本地」这一类，而不是落到「未知」 |
| IPC | `insight:getPricing` / `insight:setPricing`（校验：模型名非空、单价为非负数） |
| UI | 「模型对比 → 使用量排行」页的「今日成本」卡片加「定价设置」→ 选/输模型名 + 输入/输出单价 |
