# NOVA #009 — M4-R 剩余界面实跑

> **状态**：已实现（2026-11-18）
> **对应台账**：DEV-164
> **分支**：`feat/harness-wiring`
> **前置**：[M4-Q e2e 进 CI 门禁](NOVA-#009-m4q-e2e-ci-gate-design.md)

## 一、为什么做这件事

M4-Q 定的顺序是：**先把「跑」变成「门禁」，再实跑剩余界面**。本批做第二件。

M4-K 留过一句：

> 「首屏之外仍有未实跑的界面 —— 其余页面（Skills / Models / IM / Schedule / Settings /
> DevPanel 展开态）**仍只过 typecheck 与组件测试**」

而这几批挖出的 P0 —— Chat 整屏红屏、发送按钮被压、MCP 沙箱假成功 ——
**全是实跑才看见的**。typecheck 与组件测试都没报。

## 二、做法

新增 `tests/e2e/verification-pages.spec.ts`（7 例），把每个页面**逐个真跑**，
每页断三件事：

| # | 断什么 | 为什么 |
|---|---|---|
| ① | 页面**根容器**真的渲染了 | 「页面加载成功」不等于「界面出来了」 |
| ② | 页面**该有的关键内容在**（不是只有标题） | 空壳页面也满足① |
| ③ | **没有红屏兜底**（`[PiPiClaw render error]`） | M4-K 的 P0 就是这个形态 |
| ④ | 关键元素**完整落在视口内** | 防 M4-O 那类「靠右的元素被裁」 |

| 页 | 根容器 | 关键内容 |
|---|---|---|
| 技能管理 | `.skills-page` | 技能目录卡 · 技能验证(受控对照)卡 · **「浏览 ClawHub 市场」**（M4-M 新增） |
| 模型管理 | `.models-page` | 「添加提供商」· **「对比模型」**（M4-M 新增） |
| IM 管理 | `.im-management` | `.im-tabs` |
| 定时任务 | `.schedule-page` | `.schedule-intro` |
| 设置 | `.settings-page` | `.settings-nav__btn` · 主题 `.radio-group` |
| DevPanel | `.dev-panel .dev-body` | 内容非空 + 含 `FPS` |
| 设置 5 个页签 | `.settings-panels` | 逐个点过去，每个都要有内容 |

**设置页的页签要逐个点**：不点 = 永远不知道那个页签有没有问题。

每页留一张存档图（`test-results/page-*.png`），人工可查。

## 二点五、过程中挖出：e2e 的「隔离」只隔开了开发者 profile，**没隔开 spec 文件之间**

新增的「剩余界面实跑」spec **单独跑全绿**，放进全量套件却红一条
（「模型管理页缺关键内容:button:has-text("添加提供商")」）。

**根因**：M4-K 的隔离修复把 userData 目录建在**模块级**：

```ts
const sharedUserDataDir = mkdtempSync(...)   // 模块加载时执行一次
```

而 Playwright 在同一个 worker 里**顺序跑多个 spec 文件**，Node 的模块缓存让这个 helper
**只被加载一次** → **所有 spec 文件共用同一个 userData** → 状态在文件之间泄漏。

**实测泄漏的东西**：`ui-smoke` 切到 English 后**没切回来** → 下一个 spec 文件启动时
语言仍是英文 → 依赖中文文案的断言全红（而单跑那个 spec 是绿的）。同类还会漏：provider、
会话、主题。

> **为什么之前没暴露**：M4-K 修的是「别写开发者真实的 %APPDATA%」—— 那条成立且有效，
> 但**没解决 spec 文件之间**的隔离。

**修法**：userData 改成**每个测试一个**（应用本来就是每个测试重启一次 →
零额外成本，状态彻底不串）；清理时加护栏（只删「系统临时目录下 + 前缀 pipiclaw-e2e-」的目录）。

### 连带暴露：一批**顺序依赖**的 spec

改成每测试独立 profile 后，一批 spec 立刻红了 —— 它们**一直依赖同文件内前面测试留下的状态**：

| spec | 依赖 |
|---|---|
| `settings-full-crud` CR2/CR3/CR4/CR6/CR7 | 依赖 **CR1** 建的 provider（CR4 更依赖 **CR3** 改名后的名字） |
| `network-failure` NW4 | 依赖 **NW1/NW3** 建的两个 provider（它断言删掉 2 个） |

**这些用例单跑必红**，以前只是靠「跑全量时前面刚好有」才绿 —— 也就是说**从没被单独验证过**。
现改为每个测试自建前提 → 用例之间彻底无关（顺带能并行跑）。

> **教训**：共享 profile 会把「用例依赖彼此」这件事**藏起来**。隔离做对之后这种依赖会自己
> 冒出来 —— **冒出来是好事**。

### 每测试独立 profile 的代价与化解

改成每测试独立 profile 后，**每个测试都从「全新安装」起步** → 首启引导要走一遍（4 步）
+ 等 toast 自己消失（~3s）→ 全量从 8 分钟涨到 19.8 分钟。

化解：引导走完后**把 toast 隐藏**（`display:none`，**不是移除 DOM** —— 移除会让
Element Plus 到点自己 unmount 时可能对已脱离的节点报错）→ 不挡点击、不动它自己的生命周期，
且不用等它消失。首启引导本身**仍然每个测试都走一遍**（真实的新用户路径，不预置配置绕过）。

## 三、结果

**本批未发现新的产品缺陷** —— 5 个页面 + DevPanel 展开态 + 设置页 5 个页签全部正常。

顺手验了个看着可疑的点：技能页页头三个按钮（智能去重 / 导入技能 / 浏览 ClawHub 市场）
在截图里像被右边缘裁掉了。**量了才知道没裁**：按钮右边缘 1268 < 视口 1280
（正好是页面内边距）。教训同 M4-O：**量，别看截图猜** ——
但顺手把「关键元素必须完整落在视口内」写成了断言，防同类回归。
