## 一、为什么要做

M4-W 量出「选对率 100%」—— 但那是在 **4 个技能**上量的。
M4-X 的开源技能库一次能装 30+ 个。**列表一变长，还准不准没人知道。**

这是 M4-W 遗留 #1 原话：「技能多起来时路由会不会退化（列表太长、描述互相重叠）还没量过」。

## 二、基准怎么设计

`tests/integration/skill-routing-scale-live.test.ts` —— 接**真模型**，
走**生产 agent 路径**（`LlmAgentBrain.run`），与 M4-W 同一套指标与四条约束
（id≠name / 每任务只匹配一个 / 带负样本 / 措辞不提技能名）。

**唯一的变量：技能数量 4 → 24。**

| 组成 | 数量 | 说明 |
|---|---|---|
| 目标技能 | 10 | PDF / Excel / commit / 图片 / 幻灯片 / 日志 / SQL / Docker / JSON / 正则 |
| 填充技能 | 14 | 代码审查 / API 文档 / 数据库迁移 / 目录 / 图表 / 抓取 / 邮件 / 纪要 / 重构 / 安全审计 / 测试用例 / 发布清单 / 摘要 / 定时任务 |
| 任务 | 13 正样本 + 3 负样本 | 负样本的正确行为是**不加载任何技能** |

### 2.1 一个测量教训：先冻住输入，再谈结果

第一版填充集是**每次从开源索引实时拉**的。实测每轮可用条目在 **11~18 个**之间波动
（网络 / 限流 / 关键词过滤），于是同一份代码跑出 55.6% / 77.8% / 77.8% / 100% ——
**测到的是网络波动，不是被测行为。**

改法：把 14 个填充**写死**（主题各异、描述按真实技能写法、不含目标关键词）。
之后再跑：**100% / 92.3% / 92.3%**（第 4 轮 12/13）。

## 三、量出来的结论

### 3.1 规模本身不是主要风险

| 技能数 | 选对率（qwen3.5:9b） | 漏选 | 多选 | 负样本误触发 |
|---|---|---|---|---|
| 4（M4-W） | **100% × 3 轮** | 0 | 0 | 0 |
| **24**（本批） | **100% / 92.3% / 92.3%** | 0 / 1 / 1 | **0** | **0 / 3 每轮都是 0** |

24 个技能时约 **95%**，比 4 个技能低一点，但**没有崩**；而且**多选始终是 0**
（不会因为列表长就一口气加载好几个）。技能清单注入长度约 6k 字（≈3k tokens）——
没有把提示词撑爆。

### 3.2 真正的原因是**描述没覆盖用户的说法**

唯一稳定复现的那个漏选是：

> 任务：「**扫一份扫描版PDF，把里面的文字识别出来**」
> 目标技能描述：「从 PDF 中提取文本与表格，**导出为 CSV 或 Markdown**」

描述里没有「扫描」「OCR」「识别」这类词 → 模型没把它认成"相关"。
**这不是"技能太多"的问题，是"这个技能没说自己能干这个"的问题。**

对产品的含义：
- 规模（列表长度）不是首要矛盾 —— 不必急着做"分组/折叠/分层"。
- **技能描述质量**才是路由的关键（M4-W 已经量到同一件事的另一个切面：
  摘要里没有 id 就选不对）。
- 从开源库装的技能，描述是上游写的 → 装完**值得提示用户/自动补全 when_to_use**
  （M4-X 的安装流程已经会由标签合成 when_to_use，但没覆盖"OCR"这类同义说法）。

### 3.3 主题重叠才是最危险的情形

在"实时拉真实条目"的那版里，填充技能含 `xlsx`（Excel 类）。
27b 模型在两条 Excel 任务上都选了 `xlsx` 而不是目标技能 → 那轮 44.4%。

但**这未必是模型错**：两个技能都真的相关。它说明的是：
- **主题重叠时，"唯一正确答案"这个前提不成立** —— 基准本身要先排除歧义，
  否则测出来的是"歧义程度"，不是"选择能力"。
- 对产品：用户装了两个同类技能时，AI 选哪个都可能合理；
  这时更该关心的是「两个都加载会不会互相冲突」，而不是"选错"。

### 3.4 更大的模型不等于更稳

27b 那轮 44.4%（16 个技能）反而低于 9b；与 M4-J 的发现一致
（换更大的模型，偏置反而更大）。**路由能力不能只靠"上个更大的模型"解决。**

## 五、遗留与后续

| # | 遗留 | 说明 |
|---|---|---|
| 1 | 只有 1 个模型 × 3 轮 | 样本仍小。要把"约 95%"当结论，需要更多轮次与更多模型 |
| 2 | 填充集是**写的**不是**拉的** | 为了可比性牺牲了真实分布。建议：冻结一份**真实**索引快照（离线 fixture），兼顾真实与可重复 |
| 3 | 只在 ascii/中文任务上测 | 开源库大量英文技能 + 中文用户的组合没有单独量过 |
| 4 | 没有"多技能冲突"实验 | 3.3 指出的方向：两个同类技能同时被加载时会发生什么 |
| 5 | 描述质量 → 安装时补全 | 3.2 的落地项：从开源库装的技能，按上游描述补 `when_to_use` 的同义词（如 OCR/扫描件） |
