# NOVA #009 — M4-M 低频功能的入口：侧栏加图标，还是放回意图现场？

> **状态**：已实现（2026-11-12）
> **对应台账**：DEV-149
> **分支**：`feat/harness-wiring`
> **前置**：[M4-L e2e 套件对齐](NOVA-#009-m4l-e2e-alignment-design.md)

## 一、要决定什么

M4-L 把 51 个既有 e2e 失败归零时，暴露出一件事：**ClawHub 技能市场**与**模型对比**
这两个页面在 v4.4 把侧栏收成 7 个固定图标时**丢了侧栏入口**：

| 页面 | 现状的入口 | 上手难度 |
|---|---|---|
| `/clawhub` 技能市场 | ① Ctrl+K 命令面板 ② 「导入技能」对话框里的一个页签 | ②要先进"导入"对话框才知道有"从 ClawHub 导入"这个页签 —— **2 层深** |
| `/model-compare` 模型对比 | **只有 Ctrl+K** | 用户必须**事先知道**这个快捷键 —— **0 个可见入口** |

**要回答的问题**（用户原话）：「对比同类型产品，哪个方式对于用户上手难度更低用哪个」。

## 二、同类产品怎么做的（检索结论）

| 产品 | 市场/插件的入口 | 模型相关入口 | 一级导航的规模 |
|---|---|---|---|
| **Claude Code** | `/plugin` —— 一个显式命令，打开带 Discover / Installed / Marketplaces / Errors / Stats 页签的管理面板 | — | 不塞进导航栏 |
| **Cursor** | Activity Bar 一个图标（四宫格）；**图标多了就进「…」溢出菜单**；另有侧栏里的 Customize 页 | — | 溢出是官方认可的降级方式 |
| **Cherry Studio**（最接近的同类：国产桌面 AI 客户端） | **设置 → Agent 设置 → 插件** 页签 —— 在**相关页面里**，不是一级图标；另有「助手市场」走侧栏智能体按钮 | 多模型同屏对比是其**招牌能力** | 侧栏是**助手/Agent 列表**，不是功能目录 |
| **OpenChat UI 设计系统** | 主导航只有 **Chats / Models / Settings** 三项；模型管理**放二级**，"不与主要对话目的地竞争" | 同上 | **3~5 项** |
| **飞书（Agent 类入口案例）** | 低频应用进「更多」，**保留可发现性又不占主导航空间**；用户可自行重排/隐藏 | — | 主导航留给高频 |
| **通用导航启发式**（BrowserMoon / UIGuides） | "水平栏约 6 项就到顶"；"**多数导航问题先出在信息架构，不是视觉设计**"；建议渐进披露 | — | — |

### 两条结论

1. **同类 AI 客户端（不是 VS Code 派生的 IDE）都不把"市场"放一级图标导航**：
   Cherry Studio 放在「设置 → Agent 设置 → 插件」，Claude Code 用一个显式命令，
   OpenChat 明确写"主导航只留高频目的地，低频功能放二级"。
   Cursor 那种"一个图标 + 溢出"是 **VS Code activity bar** 的既有心智模型 ——
   那一栏的图标是 Explorer/Search/Git/Extensions，用户早就在 VS Code 里学过了；
   PiPiClaw 是一条**产品导航 rail**，没有这种先验。
2. **识别 vs 阅读**：图标栏是**无文字**的，用户要靠*识别*某个图形；
   带文字的按钮靠*阅读*。对新用户，**阅读的门槛低于识别**。

## 三、决策

**两个页面都不进侧栏**，改成在**意图发生的现场**放一个带文字的按钮：

| 页面 | 入口 | 路径长度 | 记忆负担 |
|---|---|---|---|
| ClawHub | 技能管理页头部「浏览 ClawHub 市场」 | rail → 技能管理 → 按钮 = **2 击** | 无（按钮有字） |
| 模型对比 | 模型管理页头部「对比模型」 | rail → 模型管理 → 按钮 = **2 击** | 无（按钮有字） |

对照原方案：

| 方案 | 路径 | 问题 |
|---|---|---|
| 只留 Ctrl+K | 快捷键 → 输入 → 确认 | **要事先知道快捷键**；新用户根本不会发现 |
| 侧栏加图标 | rail → 图标 = 1 击 | 无文字 → 靠识别；且 rail 变 9~10 个等权图标，**稀释 Chat/Models/Skills 这些主目的地**（OpenChat/飞书都警告过这点） |
| **本次采用** | rail → 相关页 → 文字按钮 = 2 击 | 多一次点击，但**零记忆负担 + 有文字可读 + 不稀释主导航** |

选它的另一个理由：**这两个页面本来就是"某个功能内部的二级面"**——
ClawHub 是技能体系的市场，模型对比是模型管理的对比。放在母页面里，符合用户心智。

**Ctrl+K 保留**（熟练用户的快路径，CommandPalette 里本来就有这两项，无需改动）。

## 四、实现

| 文件 | 改动 |
|---|---|
| `src/views/SkillsView.vue` | 头部加「浏览 ClawHub 市场」按钮 → `router.push('/clawhub')`；图标 `Goods` |
| `src/views/Models.vue` | 头部加「对比模型」按钮 → `router.push('/model-compare')`；图标 `Switch`；文案走 i18n `models.compare` |
| `src/locales/{zh-CN,en-US}.ts` | 新增 `models.compare` |

> SkillsView 整页是硬编码中文（既有状况），故按钮与邻居保持一致用中文；
> Models 页走 i18n，故加 `models.compare` 中英两条。
