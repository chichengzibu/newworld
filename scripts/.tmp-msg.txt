feat(m4-i): 轨迹签名聚类 — 学习闭环不再只认字面相同的指令

旧实现的聚类键是**归一化后的指令文本**。于是「整理一下桌面」与「收拾下桌面」
**做的是同一套动作**却分成两簇,各自支持度 1 → 低于门槛 → **永远不提提案**。
而「同一件事的不同说法」恰恰是最值得学的模式 —— 用户不会每次都一样措辞。

按你的要求先做了 GitHub/论文对比,四个独立工作收敛到同一结论:
  - TraceGraph(arXiv:2605.31308):每步编码成稀疏可观察键(动作/工具类型、观察模式、
    上下文线索),相似度用**键重叠**算,**不依赖提示词文本** —— 明确指出按提示词聚类
    会丢掉有区分度的那个维度
  - Hierarchical Clustering of Agent Traces(2026-05):对 agent 轨迹存在**结构行为信号**
    (tool_call_sequence = 去重后的有序工具名、distinct_tools_invoked、tool_error_count…),
    而 chat 日志没有这些 —— 按提示词聚类等于扔掉区分维度
  - AgentTrails(arXiv:2607.18816):把日志转成数据流图后**跨运行对齐**,
    高支持度的簇被提议用来播种可复用技能库
  - Microsoft context-intelligence-gds:Session→Tool 二部图 + nodeSimilarity(Jaccard)/
    fastRP/node2vec 找「角色等价但邻居不完全相同」的会话;
    并警告**比较前必须加权**,否则被胶水工具主导

实现(electron/learning/TrajectorySignature.ts)
  - toolOf 认三种步骤形状(agent loop 的 name / TaskExecutor 的 type·action / 旧的 description)
  - signatureOf:轨迹用到的工具,有序去重
  - computeIdf:**平滑 IDF** log((1+N)/(1+df))+1
  - similarity:加权 Jaccard(Σmin / Σmax,权重必须参与两侧)
  - clusterBySignature:贪心聚类(轨迹量级只有几十~几百,层次聚类的 O(n²) 没必要;
    贪心结果**可解释**;且**确定性** —— 同批观察两次聚类结果相同,才能做回归对比)

实现期踩到并修掉的坑
  - 裸 IDF log(N/df) 下,出现在**全部**轨迹里的工具权重为 0。而分析窗口常常只有几条
    → **每个工具**都在所有轨迹里 → 权重全 0 → 相似度恒 0 → **一条都聚不到**
    (实测:2 条相同动作的轨迹聚不成簇)。平滑 IDF 权重恒 ≥ 1,任何规模都能算;
    罕见工具权重仍显著高于胶水工具(N=4 时 2.22 vs 1.0)
    → 胶水压制从「绝对归零」变成「相对降权」,效果一样但不会把小语料打瞎

指令文本没白扔
  聚类**键**换成轨迹签名,但簇的**代表指令**取簇内最高频那条 —— 提案用用户自己的话
  才贴切。没有轨迹的老数据(M4-C 之前落盘)退回按指令分组,不被丢掉。
