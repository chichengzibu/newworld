refactor(m4-g): 架构收敛 — 删掉没接入主线的平行架构

M3-F 把被误删的模块恢复了 —— 但它们仍是**没接入主线的平行架构**。
本批收敛:仓库里曾同时存在三套技能运行时 + 两套 agent 实现 + 一套 actor 模型。

平行架构(DEV-096)
  runtime/actor + runtime/conversation 来自 #005 时期,当前设计文档
  (NOVA #003~#009)从未提及 → 从未注册过任何 actor,
  IpcBridge 里「查 registry → 投给 actor」那段**永远走不到**;
  conversation 6 状态机同样未接入,只被 AgentBrain 当类型挂着。
  删掉:IpcBridge 瘦身为纯 EventBus 桥接(**行为一字不变**,那段分支本就不可达),
  IpcBridgeMessage.from 类型从 ActorId 改为 string(它本来接收任意来源标签)。
  为什么删而不是接上: 它不是规划中的架构,是个没有落点的实验。
  而 SkillManager 那次已证明「平行架构」的代价 —— 每次读代码都要先判断「哪个是真的」。

永不赋值的字段(DEV-097)
  AgentBrain 挂着 conversation 字段,setConversation 零调用方 → 恒为 null
  → conversationId 恒为 'unknown'。现删掉字段与方法,直接写明常量
  (不再假装它会变)。

渲染进程类型检查进构建门禁(DEV-098)
  M3-F 只给主进程加了门禁,vue-tsc 只在 npm run typecheck 单独跑、构建不碰
  → 渲染层类型错误同样是「构建能过、运行时炸」。
  现构建 5 步: 主进程 typecheck / 渲染进程 typecheck / vite build /
  electron-builder / build-report。

导入完整性护栏扩到 tests/(DEV-099/100)
  测试文件 import 已被删的模块,同样会让 vitest 整个文件 0 test
  (报「Failed to resolve import」,不是断言失败)—— 本批就撞上了
  (MessageQueue.test.ts)。护栏扩到 tests/;零字节空壳检查同样扩展。
  顺带修护栏自身的 bug: 解析候选里没放**原样路径** → import X from './X.vue'
  被拼成 X.vue.vue → 一片假警报。已把原样路径放进候选首位。

顺带删除 tests/unit/MessageQueue.test.ts(只测已删的模块)
