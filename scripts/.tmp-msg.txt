feat(m4-f): 用户接受度 + LLM 裁判层 — 成功信号从「过程」到「用户满不满意」

M4-E 判的是**过程**(工具全成功/有答复/结构约束),不是「用户满不满意」。
而技能值不值得留,最终是用户说了算 —— 业界把用户反馈当**主指标**
(trace-to-eval:用户点踩 → 进评测集 → 下次改动对着真实失败回归)。

用户接受度(AcceptanceLog)
- 可采集的信号:点了「重新生成」= 明确不要(**最强** —— 用户主动花一次 token 换答案);
  下一条消息以纠正词开头 = 不满意;以认可词开头 = 满意;都没命中 = unknown
- **只认句首的词**:「不是」「不对」在正常任务描述里也常见
  (「把**不是**苹果的挑出来」「**不对**称的那些别动」)→ 全文匹配会把大量
  正常后续指令误判成「不满意」,而误判的代价是**让效用统计偏悲观**,比没有统计更糟
- 同理「用户没再说话」**不算满意**(可能只是走开了)→ 记 unknown,不猜
- **接受率分母只算有明确信号的**(accepted+rejected),unknown 不进分母 ——
  否则「用户根本没用这个技能」看起来像「用户不满意」
- 链路:运行先登记(用户信号是事后才有的)→ 渲染层在下一条消息发出前查上一条
  助手消息判定,只把「重新生成」上报 rejected
- 界面:「技能管理 → 边际效用」面板新增「用户接受度」列(无信号显示「无信号」不显示 0%)

LLM 裁判层(RunJudge)
- 可注入 → 单测注假裁判不联网;生产用本地 ollama 小模型
- 提示词按 **pairwise 对比口径**写(业界:pairwise 比绝对打分可靠)+ 3~5 条明确标准
  + 强制结构化输出
- **确定性采样**(按序号取模,不用 Math.random)→ 同批样本两次评估可比、可做回归;
  默认采样率 0.05(业界建议 2~5%)
- 解析容错(```json 包裹/前后废话);**pass 非布尔 → 视为不可解析**(不当成 false
  —— 把不确定当成否定);**裁判不可用 ≠ 失败**(模型报错记「不确定」)
- **裁判层不参与 pass/fail** —— judge drift 真实存在(换模型/换提示词/换顺序都改结果),
  让它改结论就是让结论随裁判模型漂移;它只进综合分与说明
- 默认不跑:生产路径不传 judge —— 采样率/漂移/成本都需用户显式开启

实现期自己抓到的三个问题
- registerRun 会**覆盖已有判定** → 信号先到、登记后到时判定被冲成 unknown,信号丢失
  (改为:已有记录时保留原判定)
- preload 出现**两个 learning: 块**(我新增的与既有的 getStats 等撞名,TS1117)→ 合并进既有块
- 裁判的 provider 类型不含 'ollama'(本项目的 ollama 走 openai-compatible 适配器)
