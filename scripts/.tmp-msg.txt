test(m4-h): 面板渲染测试 — typecheck 通过 ≠ 界面正常

本批新增的 6 个 UI 面板此前只过了 typecheck 与构建 ——
**typecheck 通过 ≠ 模板能渲染 ≠ 数据能落到界面上**。
M4-G 靠人工实跑 + 截图抓到了问题(i18n 缺 key、flaky 断言),价值真实,
但**人工截图不可回归**:下次改模板又坏了没人知道,且覆盖不全。

新增 18 例组件测试(用**真 Element Plus** 渲染,不用 stub)
  - tests/unit/skills-m4-panels.test.ts(10 例)—— SkillsView 的 4 个面板
  - tests/unit/m4-panels-settings-cost.test.ts(8 例)—— 设置页嵌入后端卡片
    + 模型对比页今日成本卡片

守的是「用户能不能看到该看到的东西」
  - 数据为空时**不该占位**(空卡片比没卡片更糟)
  - 有数据时关键字段必须在 DOM 里(「+50%」「100%」这类值)
  - 判定的**中文标签**必须正确(用户看不懂 insufficient_data)
  - **诚实标注是重点**:伪向量时必须说「召回是噪声」;
    无信号时显示「无信号」而非 0%;样本不足时明说「样本不足」而非给差值
  - 成本告知不能省:未选技能直接拒绝(不白跑模型);开始前必须弹确认,
    且确认框里要说明 token 翻倍

两个技术要点
  - **不用 stub 组件**: el-table 的列内容(el-table-column 的 default slot)是
    **按行**渲染的,stub 掉它表格里的值根本不会进 DOM —— 只能验到静态文案,
    验不到「数据真的落到界面上」。故用真组件验真实渲染路径。
    唯一例外是 el-tabs/el-tab-pane:它们只渲染被激活过的 tab,
    「今日成本」卡片在默认 tab 下不在 DOM 里 → stub 掉 tab 容器让它渲染所有 pane。
  - **顺带钉住 handler 与组件的形状约定**: insight:cost:today 真实返回**扁平**
    结构(totalCostUsd/totalInputTokens/byModel/recent 同级),而我第一版 mock
    写成了 {today:{...}} 嵌套 → 组件读不到 → 「按模型分布」那栏测不出来。
    **生产代码是对的**,是 mock 没照契约写。已对齐 —— 这正是组件测试的价值:
    今后谁改形状都会红。
